# Identity migration staging

The currently installed `com.axs.dafeiyupet` is not replaced by this staging work. `Sources/MowangDaFeiYuPetMigration.h` contains isolated migration helpers for a possible later, explicitly authorized migration to `com.mowang.dafeiyupet`. No production caller invokes them: reading or writing new preferences and sending a chat message use only the new identity. Neither helper deletes the legacy data. The preference helper copies a validated, whole dictionary only when the destination does not exist; the new file is atomically published through a same-directory temporary file and an exclusive hard link. The Keychain helper checks whether the destination exists first and never overwrites it. It returns an error if the host cannot read the legacy entry; no secret is written to a log or repository. These helpers are not a verified migration workflow and must not be invoked on real data without the user's authorization.

Build and test: `apelin_project_build` runs `apelin/build.sh`. For the isolated synthetic preference test, compile `tests/Migration.m` for arm64 with ARC and Foundation/Security to `build/migration-test`, sign it with `ldid -Stests/Tool.entitlements build/migration-test`, then run it. This checks no overwrite, unchanged source, invalid dictionary rejection, and query attributes, **not Keychain entitlement or access**. Do not run production migration until the new identity and host access are validated. In particular, the prior independent Keychain test returned -34018 and tells us nothing conclusive about SpringBoard access. No package swap is permitted until the user's prerequisite of reliably verified settings and Keychain migration is met. Keep the previous build and git history available for rollback.
